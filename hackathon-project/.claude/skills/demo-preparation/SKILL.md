# Demo Preparation

## Inputs
- Judging criteria and demo slot length (`CLAUDE.md`)
- Demo storyline (`requirements/requirement-analysis.md`)
- Validation status (`deliverables/validation-matrix.xlsx`)

## Outputs
- `deliverables/demo-script.md`
- `demo/screenshots/` — one PNG per demo step, named `01-<step>.png`
- `demo/demo-video/` — backup recording (MP4, 1080p, ≤ 3 min)

## Story structure (for a ~5-minute slot)
| Time | Section | Purpose |
|---|---|---|
| 0:00–0:30 | Hook & problem | A relatable user and a number that shows the pain |
| 0:30–1:00 | Solution in one sentence | What it is, who it's for |
| 1:00–3:30 | Live demo | 3–5 steps following one user's journey |
| 3:30–4:15 | Under the hood | Architecture and what's technically hard/novel |
| 4:15–4:45 | Impact & next steps | Business value, scale, roadmap |
| 4:45–5:00 | Close | Team, ask, thank you |

## Steps
1. Map each judging criterion to a moment in the script.
2. Write the script with exact words, clicks and expected screens per step.
3. Prepare demo data: realistic names and values; reset script to restore it.
4. Capture screenshots for every step; record a backup video of the full flow.
5. Prepare a short slide deck if required (problem, solution, architecture, impact, team).
6. Write likely judge questions with crisp answers.
7. Rehearse at least twice with a timer; assign who speaks and who drives.
8. Pre-demo checklist: charged laptop, offline fallback, browser zoom, notifications off, tabs pre-opened, logged-in state.

## Rules
- Show, don't tell. Every claim is backed by something on screen.
- Never demo an untested path live.
- Always have the backup video one click away.
